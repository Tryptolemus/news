# MetaFlora News: web push alerts

Readers subscribe with the bell in the header and get a browser or phone notification when a story matching their topics is published. Free for readers (no app, no account, no credits) and free to run: Firebase Cloud Messaging has no per-message charge, and everything else fits Firebase's free Spark plan and GitHub Actions.

## How it works

| Piece | Where | What it does |
|---|---|---|
| Bell + preferences panel | `newsroom/notify_site.py` (HTML), `newsroom/assets/notify.js` | Opt-in, topics, frequency, status, turn off. Loads nothing from Firebase and asks for no permission until the reader clicks **Turn on alerts**. |
| Service worker | `docs/firebase-messaging-sw.js` (generated by the build) | Shows alerts and opens the story when tapped. No caching. |
| Web app manifest + icons | `docs/manifest.webmanifest`, `docs/assets/icons/` | App name and icon for "Add to Home Screen" (required for alerts on iPhone/iPad). |
| Subscriber records | Firestore `devices/{deviceId}` | Anonymous device ID, push token, topics, frequency, platform, timestamps. Locked down by `firebase/firestore.rules`. |
| Dispatcher | `newsroom/push.py` + `newsroom/notify_logic.py` | Matches stories to subscribers, sends through FCM in batches of 500, removes dead subscriptions, logs every send. Runs only in GitHub Actions. |
| Automatic alerts | `push-alerts` job in `.github/workflows/publish.yml` | After every deploy that adds stories. Never blocks publishing. |
| Admin controls | `.github/workflows/notify.yml` (Actions tab, **Run workflow**) | preview, test, send, status, digest. Daily digest runs at 08:00 Bucharest. |
| Dashboard | `/admin/notifications/` (noindex, robots-disallowed) | Subscribers, growth, sends, failures, clicks, test devices, alert preview. Google sign-in; admins only. |
| Article fields | `breaking`, `push`, `draft` in `content/articles/*.json` | See NEWSROOM.md. |

### Topics (mapped onto the site's existing sections)

| Bell topic | Sections |
|---|---|
| Breaking news | any story marked `"breaking": true` |
| US cannabis policy | Policy, Federal, States |
| Federal hemp legislation | Hemp |
| Cannabis business, markets and stocks | Markets |
| Science and medical research | Science |
| Technology and innovation | Tech |
| International cannabis news | Europe |

"Industry & business" and "Markets & stocks" share the one Markets section, so they are one topic rather than two that would always fire together.

### Frequency

- **Breaking news only**: only stories marked breaking.
- **Every new story in my topics**: each matching story. To avoid floods, a device gets at most 2 separate alerts per edition; 3 or more matching stories arrive as one "N new stories in your topics" alert that opens the front page. Breaking stories always arrive on their own.
- **One daily digest**: one alert each morning summarising the last 24 hours in the reader's topics (only if there were any).

### Safety rails

- **Dry run by default.** Until the repository variable `PUSH_LIVE` is `1`, every send is an FCM dry run: fully validated, delivered to no one, logged as `dry-run`.
- **Once per story.** `sends/<article key>` is created atomically before sending; retries, edits and re-commits are skipped as "already sent". Each day's digest is also sent once.
- **Tests reach admins only.** `test` sends only to devices an admin registered on the dashboard, titled `[TEST]`, and never uses up the story's real send.
- **Manual sends need confirmation.** `send` refuses unless `confirm` is exactly the article key.
- **Not for drafts, future-dated or old stories.** `draft: true` stories aren't built at all; stories dated more than 2 hours ahead or older than 48 hours aren't alerted.
- **Dead subscriptions** (FCM `UnregisteredError`) are deleted automatically; other errors never delete anything.
- **Never blocks publishing.** The job is `continue-on-error`, and the script catches everything and exits 0.
- **Credentials** live only in the `FIREBASE_SERVICE_ACCOUNT` secret. The web config in `newsroom/firebase-web.json` is public by design.
- **Abuse limits.** Firestore rules allow one record per anonymous device, validate every field, and throttle each device to one change every 3 seconds; Firebase caps anonymous sign-ups per IP.

## One-time setup

1. **Create a Firebase project** (console.firebase.google.com), e.g. `metaflora-news`. Spark (free) plan. Google Analytics is not needed.
2. **Authentication**, Sign-in method: enable **Anonymous** and **Google**. Settings, Authorized domains: add `news.metaflora.xyz`.
3. **Firestore Database**: create in production mode, location `eur3` (Europe). Deploy the rules from this repository:
   `npx firebase-tools deploy --only firestore --project <project-id>`
4. **Register a web app** (Project settings, General, Add app, Web). Copy `apiKey`, `authDomain`, `projectId`, `messagingSenderId`, `appId` into `newsroom/firebase-web.json`.
5. **Cloud Messaging**, Web configuration, Web Push certificates: **Generate key pair**. Copy the public key into `vapidKey` in `newsroom/firebase-web.json`. Set `"enabled": true`.
6. **Service account** (Project settings, Service accounts, Generate new private key). Store the whole JSON as a repository secret named `FIREBASE_SERVICE_ACCOUNT`, then delete the downloaded file:
   `gh secret set FIREBASE_SERVICE_ACCOUNT -R Tryptolemus/news < key.json`
7. **Make yourself an admin.** Open `/admin/notifications/`, sign in with Google. The page shows your user ID. In Firestore, add a document `admins/<that id>` (any field, e.g. `name`). Reload.
8. **Register a test device.** Turn on alerts with the bell in your browser, open the dashboard, click **Register this browser as a test device**.
9. **Test** (still dry run for readers): Actions, Notifications, Run workflow, action `test`. You should get a `[TEST]` alert.
10. **Go live:** repository variable `PUSH_LIVE` = `1` (Settings, Secrets and variables, Actions, Variables). Remove it to pause all reader alerts instantly.

## Admin controls (Actions, Notifications, Run workflow)

| Action | Inputs | Effect |
|---|---|---|
| preview | article key | Alert text, link, eligibility, current audience; FCM dry run |
| test | article key or blank (latest) | Real alert to admin test devices only, marked [TEST] |
| send | article key, confirm = same key | Manual send to all matching subscribers; still once per story |
| status | article key or blank | Delivery log (audience, sent, failed, removed, status) |
| digest | none | Today's digest now (normally automatic at 08:00) |

Turn off automatic alerts for one story with `"push": false`; mark urgent stories `"breaking": true`.

## Privacy

Readers opt in explicitly; the permission prompt only appears after they click the button. Stored per device: anonymous Firebase user ID, FCM token, topics, frequency, coarse platform (e.g. `android-chrome`), created/updated times; per send: counts only; per click: the alert key and the anonymous ID (one record per reader per alert). No names, emails, IP logs or browsing history. Turning alerts off deletes the device record immediately; revoking browser permission deletes it on the next visit; dead tokens are deleted on the next send. The reader-facing notice is on How we report (`/how-we-report/#alerts`). Contact: support@metaflora.xyz.

## Manual device-testing checklist

Do each on a real device with alerts LIVE only for test devices (use `test`), then once with `PUSH_LIVE=1` on a real story.

- [ ] Desktop Chrome: bell, panel, Turn on alerts, permission prompt appears only after the click; status says on; bell shows the green dot.
- [ ] Desktop: `test` alert arrives with the MetaFlora icon; clicking opens the story; dashboard click count rises by 1.
- [ ] Desktop: Save preferences (change topics) and confirm the dashboard topic counts change.
- [ ] Desktop: Turn off alerts; `test` no longer arrives; device gone from dashboard.
- [ ] Desktop: block notifications in site settings, reload: panel explains how to unblock; device record removed.
- [ ] Firefox desktop: subscribe and receive a test alert.
- [ ] Safari macOS: subscribe and receive a test alert.
- [ ] Android Chrome: subscribe in the browser, receive a test alert with the phone locked; tap opens the story.
- [ ] Android: Install app / Add to Home screen, open it, subscribe there, receive a test alert.
- [ ] iPhone Safari (not installed): panel shows the Add to Home Screen steps and no permission prompt.
- [ ] iPhone: Add to Home Screen, open from the icon, bell, Turn on alerts, permission prompt, receive a test alert, tap opens the story.
- [ ] Publish a real story to a test topic: exactly one alert; edit and re-commit the story: no second alert.
- [ ] Publish 3+ matching stories in one edition: one bundled alert.
- [ ] Mark a story breaking: breaking-only subscribers get it immediately.
- [ ] Digest subscriber receives one digest at 08:00 Bucharest the next morning, and only one.
- [ ] Phone layout: panel opens as a bottom sheet, no horizontal scroll, logo centred.
- [ ] Keyboard: Tab to the bell, Enter opens, Tab through options, Escape closes and returns focus to the bell.

## Costs

FCM web push: no charge per message. Firestore free tier: 50,000 reads, 20,000 writes and 1 GiB per day; each send reads every enabled device once, so the free tier covers roughly 20,000 subscribers at two editions a day plus the digest. Above that, Firestore's pay-as-you-go pricing (Blaze plan) is cents per 100,000 reads. Anonymous Auth: free. GitHub Actions: a few minutes per publish on the public repository.
